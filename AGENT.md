# Xmphdalf.dev

## Philosophy

Build with intention.

This project values clarity, structure, calmness, and thoughtful engineering over visual noise or trend chasing. Every component, animation, layout decision, and interaction should feel necessary.

The experience should feel human, natural, and composed.

Do not over-engineer.
Do not over-design.
Do not add complexity without purpose.

Minimal does not mean empty.
Simple does not mean careless.

---

## Engineering Principles

### DRY

Avoid duplication across:

* components
* styles
* utility logic
* layouts
* animation patterns

Abstract only when abstraction improves readability or maintainability.

Do not prematurely generalize.

### KISS

Keep solutions simple.

Prefer:

* readable code
* predictable patterns
* straightforward architecture
* small focused components

Avoid:

* clever abstractions
* unnecessary state
* over-complicated animation systems
* excessive configuration

### YAGNI

Do not build for imaginary future requirements.

Only implement:

* what is currently needed
* what improves usability
* what strengthens the experience

Avoid speculative architecture.

---

## Design Rules

The interface should feel:

* editorial
* architectural
* restrained
* intentional
* calm

Everything must respect:

* spacing rhythm
* visual hierarchy
* typography consistency
* grid structure

Whitespace is part of the design.

Do not fill empty areas without reason.

---

## UX Rules

Interactions should feel:

* soft
* tactile
* natural
* subtle

Animations must support the experience, never dominate it.

Prefer:

* opacity transitions
* gentle movement
* smooth easing
* quiet hover states

Avoid:

* flashy motion
* floating effects
* parallax
* aggressive transitions
* attention-seeking animations

The UI should feel stable and grounded.

---

## Typography

Typography carries the design.

Prioritize:

* readability
* spacing
* rhythm
* hierarchy

Avoid:

* oversized hero text
* loud gradients
* excessive font weights
* trendy typography tricks

The design should whisper, not scream.

---

## Component Guidelines

Components should:

* do one thing well
* remain readable
* stay composable
* avoid unnecessary props

Keep component APIs minimal.

Do not create abstraction layers unless they clearly reduce complexity.

---

## Styling

Prefer consistency over novelty.

Use:

* restrained color palette
* subtle borders
* soft contrast
* calm spacing

Avoid:

* random colors
* visual clutter
* heavy shadows
* shiny UI effects

Every visual element must feel intentional.

---

## Writing Style

All copy must feel:

* natural
* human
* calm
* intelligent
* grounded

Avoid:

* AI sounding phrases
* corporate buzzwords
* marketing language
* fake enthusiasm
* startup clichés

Do not write like a landing page.

Write like a thoughtful human.

---

## Code Style

Write code that is:

* clean
* understandable
* maintainable
* boring in a good way

Optimize for future readability.

A developer should understand the intent immediately without decoding abstractions.

---

## Performance

Performance is part of the experience.

Avoid:

* unnecessary dependencies
* bloated animation libraries
* excessive client-side logic
* avoidable re-renders

Prefer lightweight solutions whenever possible.

---

## Final Rule

Restraint is the entire identity of this project.

If something feels excessive, remove it.

If something exists only to impress, rethink it.

The goal is not to look trendy.

The goal is to feel timeless.
